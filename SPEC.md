## 1. Общее описание проекта

Веб-сайт с интегрированной системой управления для ресторана «Айкөл» в Бишкеке.

**Ресторан:**
- Классический интерьер
- Один большой банкетный зал до 300 человек
- Национальная и европейская кухня
- Высокий уровень сервиса
- Instagram: @aikol_restaurant (~9 600 подписчиков)

**Проект состоит из двух частей:**

| Часть | Для кого | Что делает |
|-------|----------|-----------|
| Публичный сайт | Клиенты | Просмотр меню, галереи, новостей, онлайн-бронирование зала |
| Админ-панель | Администратор ресторана | Управление бронями, меню, галереей, отзывами, новостями, настройками |

**Ключевая идея:** заменить бумажный журнал броней цифровой системой. Клиент бронирует онлайн → бронь мгновенно появляется в админке → администратор звонит и подтверждает.

## 2. Цели и задачи

### Бизнес-цели
- Увеличить количество броней банкетного зала
- Избавиться от бумажного журнала — все брони в единой системе
- Показать зал, меню и уровень сервиса потенциальным клиентам
- Укрепить бренд (единый стиль с Instagram)

### Задачи системы
- Клиент видит свободные даты и бронирует за 2 минуты
- Администратор видит все брони в календаре и таблице
- Администратор сам управляет контентом без программиста
- Сайт работает на русском и кыргызском языках
- Сайт корректно работает на телефоне (основной трафик — мобильный)

### Что НЕ входит в v1
- ❌ Регистрация клиентов / личные кабинеты
- ❌ Онлайн-предоплата
- ❌ Мобильное приложение
- ❌ Онлайн-заказ еды с доставкой

|---------|-------------|-------------|
| Семьи | Той (свадьбы, юбилеи, кыз узатуу) | Основной сегмент, бронируют вечерний слот |

- Привыкли к общению через WhatsApp

- Бронируют 1–2 раза в год → регистрация не нужна

| Медиа-хранилище | Cloudinary | free plan (25GB) |

**Почему такой стек:**

- FSD — лёгкое добавление новых фич в будущем без рефакторинга
- Prisma — типобезопасность от БД до фронтенда

## 5. Дизайн-система

### 5.1 Концепция

Дизайн полностью повторяет фирменный стиль Instagram @aikol_restaurant: **тёмный премиум + золото**. Клиент узнаёт бренд мгновенно.

### 5.2 Цветовая палитра

```css
:root {
  --color-bg:           #1A1A1A;  /* Основной тёмный фон */
  --color-bg-secondary: #242424;  /* Карточки, секции */
  --color-gold:         #C9A84C;  /* Акцент: кнопки, заголовки, рамки */
  --color-gold-hover:   #D9BC6A;  /* Hover состояние */
  --color-text:         #FFFFFF;  /* Основной текст */
  --color-text-muted:   #A0A0A0;  /* Второстепенный текст */
  --color-success:      #4CAF50;  /* Подтверждено */
  --color-warning:      #FF9800;  /* Ожидает */
  --color-danger:       #F44336;  /* Отменено */
}
```

### 5.3 Типографика

```
Заголовки (h1–h3):  Playfair Display (Google Fonts)
                    — элегантный serif, поддерживает кириллицу
Основной текст:      Inter (Google Fonts)
                    — читаемый, современный

Размеры (mobile → desktop):
h1: 32px → 56px
h2: 24px → 40px
h3: 20px → 28px
body: 16px → 18px
```

### 5.4 Компоненты UI

**Кнопки:**
```
Primary:   золотой фон #C9A84C + тёмный текст #1A1A1A
           border-radius: 8px, padding: 14px 32px
Secondary: прозрачный фон + золотая рамка + золотой текст
Ghost:     без рамки, золотой текст, underline на hover
```

**Карточки (блюда, новости, события):**
```
Фон: #242424
Скругление: 12px
Фото сверху (aspect-ratio 4:3)
Тонкая золотая рамка при hover
Плавная тень + transform: translateY(-4px) на hover
```

**Navbar:**
```
Прозрачный поверх Hero
При скролле → фон #1A1A1A с blur (backdrop-filter)
Логотип слева, меню по центру, переключатель языка + кнопка «Бронь» справа
Mobile: бургер-меню, выезжающее справа
```

**Статусы броней (Badge):**
```
⏳ PENDING    → оранжевый фон, текст «Ожидает»
✅ CONFIRMED  → зелёный фон, текст «Подтверждено»
❌ CANCELLED  → красный фон, текст «Отменено»
```

### 5.5 Адаптивность

```
Mobile first подход
Breakpoints (Tailwind):
  sm: 640px   — большие телефоны
  md: 768px   — планшеты
  lg: 1024px  — ноутбуки
  xl: 1280px  — десктопы

Обязательные требования:
- Форма бронирования удобна на экране 320px
- Календарь читаем на телефоне
- Таблица броней в админке скроллится горизонтально на mobile
- Все тач-таргеты минимум 44x44px
```

### 5.6 Анимации

```
Плавные, ненавязчивые:
- Fade-in секций при скролле (Intersection Observer)
- Hover эффекты карточек
- Переходы между шагами формы бронирования (slide)
- Скелетоны при загрузке данных
Без тяжёлых библиотек — CSS transitions + Tailwind
```

### 6.2 Правило импортов FSD

```
Импорты разрешены только сверху вниз:

app → views → widgets → features → entities → shared

❌ entities НЕ импортирует из features
❌ features НЕ импортируют друг из друга
❌ shared НЕ импортирует ничего из верхних слоёв
✅ Каждый слайс экспортирует публичное API через index.ts
```

### 6.3 Как добавлять фичи в будущем

```
Онлайн-оплата        → features/process-payment/ + entities/payment/
Email-напоминания    → features/send-reminder/
Instagram интеграция → widgets/instagram-feed/
Второй зал           → расширить entities/booking (поле hallId)
```

## 7. База данных

### 7.1 Prisma схема (полная)

```prisma
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

// ==================== БРОНИ ====================

model Booking {
  id          String        @id @default(cuid())
  clientName  String                          // Имя клиента
  phone       String                          // Нормализованный: +996XXXXXXXXX
  eventType   EventType
  date        DateTime      @db.Date          // Только дата, без времени
  timeSlot    TimeSlot
  guestsCount Int                             // 1–300
  status      BookingStatus @default(PENDING)
  notes       String?                         // Комментарий клиента
  adminNotes  String?                         // Внутренние заметки админа
  createdAt   DateTime      @default(now())
  updatedAt   DateTime      @updatedAt

  @@unique([date, timeSlot])                  // Один слот = одна бронь
  @@index([phone])                            // Быстрый поиск по телефону
  @@index([date])
  @@index([status])
}

enum EventType {
  TOI          // Той (свадьбы, юбилеи, кыз узатуу)
  CORPORATE    // Корпоратив
  QURAN        // Куран окутуу
  KIDS         // Детские праздники
  OTHER        // Прочее
}

enum TimeSlot {
  MORNING      // Вечерний той: 17:00 – 23:00
  AFTERNOON    // Дневной: 12:00 – 15:00
}

enum BookingStatus {
  PENDING      // Ожидает подтверждения
  CONFIRMED    // Подтверждена админом
  CANCELLED    // Отменена
}

// ==================== МЕНЮ ====================

model MenuCategory {
  id      String     @id @default(cuid())
  name    String                              // «Национальная кухня»
  nameKg  String                              // «Улуттук тамактар»
  order   Int        @default(0)
  items   MenuItem[]
}

model MenuItem {
  id          String       @id @default(cuid())
  name        String
  nameKg      String
  description String?
  descKg      String?
  price       Int                             // В сомах, целое число
  image       String?                         // Cloudinary URL
  isAvailable Boolean      @default(true)     // Скрыть без удаления
  order       Int          @default(0)
  categoryId  String
  category    MenuCategory @relation(fields: [categoryId], references: [id], onDelete: Cascade)
  createdAt   DateTime     @default(now())
  updatedAt   DateTime     @updatedAt

  @@index([categoryId])
  @@index([isAvailable])
}
```

## 9. Система бронирования — бизнес-логика

### 9.1 Слоты

| Слот | Время | Типичное событие |
|------|-------|------------------|
| MORNING (вечерний) | 17:00 – 23:00 | Той, свадьбы, корпоративы |
| AFTERNOON (дневной) | 12:00 – 15:00 | Куран окутуу, детские |

**Правило:** один день = максимум 2 брони (по одной на слот). Гарантируется констрейнтом `@@unique([date, timeSlot])` в БД.

### 9.2 Жизненный цикл брони

```
Клиент отправляет форму
        ↓
POST /api/bookings
  ├─ Zod валидация
  ├─ Проверка: дата >= сегодня + min_days_ahead
  ├─ Проверка: слот свободен (unique constraint страхует от гонки)
  └─ Создание со статусом PENDING
        ↓
Бронь видна в админке (Dashboard + Журнал)
        ↓
Админ звонит клиенту
        ↓
   ┌────┴────┐
CONFIRMED  CANCELLED
   ↓            ↓
Клиент видит статус на /booking/check
```

### 9.3 Правила статусов

- `PENDING → CONFIRMED` — админ подтвердил
- `PENDING → CANCELLED` — админ отклонил / клиент передумал (по звонку)
- `CONFIRMED → CANCELLED` — отмена подтверждённой (например, форс-мажор)
- `CANCELLED` — слот снова свободен для бронирования
- Отменённая бронь **не удаляется** — остаётся в истории

### 9.4 Доступность дат (API)

```
GET /api/bookings/availability?from=2026-08-01&to=2026-09-30

Response:
{
  "busy": [
    { "date": "2026-08-15", "slots": ["MORNING"] },
    { "date": "2026-08-20", "slots": ["MORNING", "AFTERNOON"] }
  ]
}
```
Считаются занятыми только PENDING и CONFIRMED (CANCELLED — свободно).

## 15. Инфраструктура и деплой

### 15.1 Схема

```
GitHub (репозиторий)
   ↓ push → автодеплой
Vercel (Next.js хостинг) — Free plan
   ↓ DATABASE_URL
Neon.tech (PostgreSQL) — Free plan
   ↓ API
Cloudinary (фото) — Free plan (25GB)
   ↓
Домен: aikol.kg (регистрация на domain.kg, ~1000 сом/год)
```

### 15.2 Порядок настройки

1. **Neon:** создать проект `aikol-restaurant` → скопировать DATABASE_URL
2. **Cloudinary:** аккаунт → скопировать cloud_name, api_key, api_secret
3. **GitHub:** создать приватный репозиторий
4. **Локально:** `.env` из `.env.example` → `npx prisma db push` → `npx prisma db seed`
5. **Vercel:** Import из GitHub → добавить все env-переменные → Deploy
6. **Домен:** купить aikol.kg → привязать в Vercel (A/CNAME записи)

### 15.3 Особенность Neon Free

- Compute засыпает после 5 минут неактивности
- Холодный старт ~0.5–2 сек — для ресторана приемлемо
- 0.5 GB хранилища — хватит на годы (текстовые данные, фото в Cloudinary)

### 15.4 Стоимость

| Сервис | Цена |
|--------|------|
| Vercel | $0 |
| Neon | $0 |
| Cloudinary | $0 |
| Домен .kg | ~1000 сом/год |
| **Итого** | **~1000 сом/год** |
